# Еженедельный цикл (автоматический)

Каждый понедельник игра сама собирает цифры, а команда агентов их разбирает и предлагает план
на неделю. Владелец получает сводку и решает. Ничего не деплоится без его «да».

## Расписание (время Киев)
| Когда | Что | Кто |
| --- | --- | --- |
| Пн 07:17 | GitHub Actions `weekly-metrics`: `scripts/fetch_metrics.py` забирает метрики за 8 дней из Open Cloud Analytics Query API → `analytics/metrics.csv`; `scripts/metrics_report.py` → `analytics/REPORT.md`; коммит в `main` | бот |
| Пн 09:00 | Запланированная задача Claude «Недельный обзор игры»: свежая сессия клонирует репозиторий, выполняет шаги ниже и делает «зелёные» авто-правки по уровню автономии | главный + агенты |
| Пн, когда удобно | Владелец читает сводку, отвечает «делаем 1 и 3» | владелец |

## Шаги задачи «Недельный обзор»
1. `gh repo clone vdmemory/sled-game`, прочитать `CLAUDE.md`, `docs/WEEKLY.md`, `analytics/REPORT.md`,
   `analytics/events.csv`, `docs/BUSINESS.md` §6 (гипотезы), `docs/IDEAS.md`, последние записи
   `docs/CHANGELOG.md`.
2. Если `REPORT.md` старше 3 дней или пустой — запустить `python3 scripts/metrics_report.py`; если
   метрик всё равно нет, в сводке так и сказать (workflow не настроен / нет трафика / API не дал
   доступ) и попросить владельца прислать скриншоты Analytics.
3. **`producer`**: прочитать отчёт, сравнить с целями и с прошлой неделей, найти узкое место
   воронки, проверить открытые гипотезы в `BUSINESS.md` §6 (сбылись/нет), предложить 3 ставки на
   неделю с ожидаемым эффектом. Обновить `BUSINESS.md` (журнал гипотез, раздел 7).
4. **`idea-scout`**: обзор `IDEAS.md` (что устарело, что подтверждают цифры), 15-минутный поиск
   новостей (DevForum Announcements, Release Notes, обновления топ-игр жанра) → 2–3 новые идеи с
   оценкой в `IDEAS.md`.
5. **`qa-tester`** (без управления компьютером — только статика): `luau-analyze` по `src/`,
   последний `gh run` зелёный, метрики стабильности из отчёта (крэши, FPS), открытые баги из
   прошлых отчётов. Если что-то красное — в сводку первым пунктом.
6. **`code-reviewer`**: техдолг недели — 1–2 пункта из `IDEAS.md`/ENGINEERING, которые дешевле
   всего закрыть сейчас.
7. Главный собирает **сводку владельцу** (≤ 20 строк): цифры недели (DAU, D1, сессия, R$, дельты),
   узкое место, 3 ставки продюсера, 2–3 идеи, красные флаги QA, вопросы владельцу. Отправить
   как сообщение сессии; закоммитить правки `BUSINESS.md`/`IDEAS.md` в `main` с сообщением
   «weekly: обзор <дата>». Строку «review» добавить в `analytics/events.csv`.
8. **Авто-правки** — по текущему уровню автономии (ниже). Всё остальное — после ответа
   владельца, в обычной сессии, через агентов.

## Уровни автономии (владелец переключает одной строкой здесь)

**Текущий уровень: 1.**

| Уровень | Что задача делает сама | Куда попадает |
| --- | --- | --- |
| 0 | только анализ и сводка | — |
| 1 «зелёные правки» | (а) техдолг и документация без изменения геймплея (линт, типы, дублирование, устаревший API по Release Notes, тексты/опечатки); (б) **баланс числами** — только параметры из `Config.TUNABLES`, не больше 3 за неделю, каждый не больше чем на ±25% от текущего и в пределах min/max, и **только если метрика это обосновывает** (≥ 7 дней данных, ≥ 300 DAU в среднем, отклонение от цели ≥ 15%); (в) исправление бага, если его показывают крэш-метрики или `luau-analyze` и правка ≤ 30 строк | push в `main` → **staging**. Production не трогается: тег `v*` ставит только владелец |
| 2 «авто-релиз» | уровень 1 + авто-тег production, если staging прожил неделю без красных флагов и метрики не ухудшились | production. Включается только после ≥ 4 недель данных и явного «да» владельца |

Ограничители на любом уровне:
- Никаких новых механик, товаров за Robux, цен Robux, изменений сейвов/DataStore, workflows,
  ассетов и ничего из «Решений владельца» — это всегда через владельца.
- Перед пушем: `luau-analyze`/`luau-compile` по изменённым файлам, `code-reviewer` даёт
  «можно пушить». После пуша дождаться зелёного `gh run`; красный — `git revert` сразу.
- Каждая авто-правка: отдельный коммит с префиксом `auto:`, строка в `docs/CHANGELOG.md`
  («Авто-правка недели: … потому что <метрика>»), строка `auto` в `analytics/events.csv`,
  гипотеза в `docs/BUSINESS.md` §6 с метрикой, по которой через неделю будет видно, помогло ли.
- В сводке владельцу — отдельный блок «Сделано автоматически» с командой отката для каждой
  правки (`git revert <sha>`).
- Если данных для (б) нет (игра не опубликована, DAU мал) — баланс не трогать, делать только (а)/(в).


## Что нужно один раз от владельца
1. **Ключ API.** create.roblox.com → Dashboard → слева **Open Cloud → API Keys** → открыть
   существующий ключ деплоя (или Create API Key) → **Access Permissions → Add API System →
   «Analytics» (universe-analytics)** → Add Experience → выбрать production-опыт → операция
   **Read** → Save. Если это новый ключ — скопировать его значение (показывается один раз).
2. **Секрет в GitHub.** github.com/vdmemory/sled-game → Settings → Environments → **production**
   → Environment secrets → Add secret: имя `ROBLOX_ANALYTICS_KEY`, значение — ключ из п. 1.
   Ключ в чат не присылать; Claude его не видит и не должен видеть.
3. **Workflow.** В репозитории: Add file → Create new file → имя
   `.github/workflows/weekly-metrics.yml` → вставить содержимое `scripts/weekly-metrics.yml.example`
   (без первых строк-комментариев можно) → Commit to main. Сессии Claude не могут создавать
   workflows (нет scope `workflow` у прокси GitHub). Проверить: Actions → weekly-metrics → Run
   workflow → через минуту в `analytics/metrics.csv` появятся строки (или warning в логе, если
   API вернул 403 — бета).
- Analytics Query API в бете: если вернёт 403, доступа у аккаунта пока нет — тогда владелец
  раз в неделю присылает скриншоты Analytics, главный заносит их в CSV руками.
