# Плейбук: как из этой игры сделать похожую (вода, суша, что угодно)

Этот репозиторий — не только «игра на санях», а **движок жанра «запуск → спуск по бесконечной
трассе → собирай → прокачивай → следующий мир»**. Сани, снег, рогатка и ракета — лишь «шкура».
Ниже — все шаги, чтобы собрать из него игру про сёрфинг, лодку, гидроцикл, надувной круг,
скейт, велосипед, машину, самокат, багги и т. п. Делать по порядку; у каждого шага — кто из
агентов (`docs/TEAM.md`) его выполняет.

## 1. Словарь новой игры (главный + `game-designer`)

| --- | --- | --- | --- |

## 2. Новый репозиторий и Roblox (владелец + `code-reviewer`)

1. GitHub → **Use this template** (или fork) → новое имя. Склонировать.
2. Roblox Creator Hub: два опыта — `<Имя>` (production) и `<Имя> [ТЕСТ]` (staging). Записать
   Universe ID и Place ID каждого (меню «⋯» → Copy).
3. Open Cloud → API Keys: новый ключ, права **universe-places: Write** на оба опыта + **Assets
   API: read + write** (иконки), IP `0.0.0.0/0`, срок действия — поставить напоминание.
4. GitHub → Settings → Environments `staging` и `production`: secret `ROBLOX_API_KEY`,
   variables `UNIVERSE_ID`, `PLACE_ID`. Ключ в чат агентам **не присылать**.
5. В репозитории: `default.project.json` → `"name"`; `scripts/upload_ui_assets.py` →
   `CREATOR_USERNAME` (или variable `CREATOR_USER_ID`). `assets/ui/decals.json` оставить: декали
   принадлежат пользователю, а не опыту, и работают в любой его игре — перезаливать не надо.
6. `src/server/DataService.luau`: имя DataStore `SledData_v1` → `<Имя>Data_v1`,
   `BestLevel_v1` → своё; `src/server/Tuning.luau`: `GameConfig_v1` → своё; топик
   `SledConfigChanged` → своё.
7. Первый `git push` → GitHub Actions → staging. Зайти, убедиться, что это ещё «сани», — значит
   труба работает. Дальше меняем содержимое.

## 3. Физика и поверхность (`game-designer` числа, `track-architect` трасса)

Все константы в `Config.luau`, раздел «ФИЗИКА». Модель: `acc = −GRAVITY_ALONG·dY − трение(ур.)
− DRAG·v²`, руль `STEER_SPEED`/`STEER_RESPONSE`, борта `WALL_PULL`, трамплин `RAMP_LIFT`/
`RAMP_MIN_SPEED`, бустер `ROCKET_THRUST`.

| Среда | Что крутить | Ориентир |
| --- | --- | --- |
| Снег (сейчас) | — | `GRAVITY_ALONG 60`, `frictionBase 9.5`, `DRAG 0.0012`, углы 2.5–5° / 12–16° |
| Вода | уклон меньше (река «течёт»: `GENTLE_ANGLE {1,3}`, `STEEP_ANGLE {6,10}`), трение чуть выше, `DRAG` выше (×1.5), `STEER_RESPONSE` ниже (инерция лодки), `WALL_PULL` слабее; волны = короткие `kicker` с малым `KICKER_DROP` | игрок должен «плыть», а не падать |
| Асфальт/грунт | `frictionBase` ниже (катится), `DRAG` как снег, `STEER_RESPONSE` выше (колёса), `STEER_TILT` меньше, `OBSTACLE_SLOWDOWN` жёстче | ощущение «гоночки» |

Поверхность и борта — `Track.buildCrossSection(cf, len, prof, chute, m, alt, theme)`: заменить
`Enum.Material.Snow/Glacier` и цвета `THEMES[*].floor/wall/ground` (для воды: дно `Glass`
0.3–0.5 прозрачности поверх непрозрачного «песка» на −1 stud, чтобы не было провалов; физика
считается по верхней части, прозрачность на неё не влияет). Профиль уровня — `buildProfile`:
набор участков (`gentle`, `steep`, `kicker`, `curve`, `road`) и их доли — оставить, но
перетюнить `Config.KICKER_CHANCE`, `CURVE_CHANCE`, `FORCED_KICKERS`.

Проверка: `qa-tester` проезжает уровень 1 и 5 — время, попытки, нет застреваний на пологих
участках (если застревает — уменьшить `frictionBase` или увеличить `GENTLE_ANGLE`).

## 4. Трасса: участки, препятствия, трафик (`track-architect`)

1. **Препятствия:** на каждый вид — карточка (роль, класс лёгкое/тяжёлое/движущееся/рельефное,
   читаемость за 2 с, размещение по полосам, логика к миру, прогрессия) — см. агента
   `track-architect`. Затем код: в `shared/Props/` (модуль своей категории) — новые функции по образцу `Props.boulder`/`Props.cones`
   (Part-ы + `Props.deco`, тег через `tagObstacle`, атрибут `Breakable` для лёгких). В
   `Props.obstacle(theme, …)` — выбор по теме. Старые снежные функции удалить или оставить как
   библиотеку (не мешают).
2. **Трафик:** `Props.traffic(theme, …)` возвращает модель-«мувер»; `Track:buildRoad` строит
   полосу и `setMover` двигает по серверному времени. Для воды — канал с лодками (та же полоса,
   другая модель и `CAR_SPEED` ниже); для суши — как есть.
3. **Особые объекты:** поезд (`Props.train`, `TRAIN_*`) и канатка (`Props.gondola`,
   `GONDOLA_CHANCE`) — заменить модель или выключить (`GONDOLA_CHANCE = 0`, `roadCount` без
   поезда — ветка `theme == 2` в `buildRoad`).
4. **Декор обочин:** `dressSegment(theme, …)` — ветка на тему: деревья/дома/горы → пальмы/
   причалы/скалы или дома/заборы/ЛЭП. Горы фоном — `Props.mountain(…, tint)`.
5. **Старт и финиш:** `Track:buildStart` (площадка + `Look`-папка с рогаткой из
   `SledModels.slingshot`) и финишная арка + «озеро» после финиша (`lake` в `buildCrossSection`,
   `FINISH_GLIDE_MAX`) — для воды озеро = бухта, для суши = ровная парковка/пляж.
6. **Лобби:** `shared/Lobby.luau`, чертёж — `Lobby.PLAN` (схема сверху в комментарии).
   `Lobby.build` (сервер, сразу) — площадка, плита-хаб, дорожка, мостик, маяк старта, Terrain;
   `Lobby.furnish` (после загрузки мешей) — ворота старта, фонари, подиумы, табло (`board`),
   костёр, флаги. `Lobby.dress(theme, parent)` и `Lobby.showcase` (клиент, `client/LobbyScene`) —
   декор по миру, витрина саней; витринная трасса — `Track.new(-1, level, 0, origin,
   LOBBY_PREVIEW_SEGMENTS)` локально. Для новой игры: заменить пропсы в `Lobby.dress` и материалы,
   поправить `PLAN` и прогнать `scripts/ui_layout_preview.py` — он проецирует путь к старту камерой
   спавна поверх UI и ловит, что плашки или сам аватар его закрывают.
7. **Борта:** невидимые стенки у края дна (`Config.WALL_HEIGHT/WALL_TILT/WALL_OFFSET`) ставятся в
   `buildCrossSection` на всех кусках, кроме жёлоба. Для воды — те же борта («буйки»), для суши
   можно ниже.
8. **Бонусы на трассе:** `make*` в `Track` (монета, гем, кристалл, магнит, щит, x2, канистра,
   кольца) — менять только вид (цвет/форма), логика на клиенте общая.

## 5. Транспорт и прокачка (`vehicle-engineer` чертёж и модели, `art-director` стиль, `game-designer` цифры)

1. `Config.SLEDS` — список моделей: `id`, `name`, `icon`, `img` (имя PNG в `assets/ui`),
   `world` (с какого мира продаётся), `bonus` (% скорости), `prices` (5 редкостей), `main`/
   `accent`. Оставить 2–3 на первый мир, остальные открывать по мирам.
2. `SledModels/Bodies`: на каждый `id` — `buildXxx(b, look)` (Part-ы вокруг невидимого
   `VehicleSeat`, см. `buildTube`), запись в `BUILDERS`, точки крепления в `MOUNTS[id]`
   (`rocket`, `spoiler`, `lights`, `flag`…) — по ним `extras` вешает обвес тиров. Персонаж
   сидит на `VehicleSeat` — для лодки/машины добавить «кабину», чтобы он смотрелся уместно.
3. **Тиры транспорта** (`Config.TIERS.Sled`, 11 названий) и обвес в `SledModels.extras`:
   сейчас фары → спойлер → обтекатель → золотой бампер → неон → флажок → крылья → хром-выхлопы →
   сияние → корона. Для лодки: фонарь → мотор побольше → ветровое стекло → хром → подсветка днища
   → флаг → подводные крылья → двойной выхлоп → сияние → корона. Менять названия и 1–2 функции
   обвеса, остальные переиспользовать.
4. **Запуск** (`Config.TIERS.Launch` + `SledModels.slingshot(tier)` 0–10 + `ROPE_COLORS`):
   рогатка — два столба + резинка-Beam. Катапульта/пушка — та же функция, другие Part-ы;
   `server/Runs` (`startRun`) перестраивает «Look» при смене тира (`ltier`). Механика «тяни и отпусти» (`Launch(power)`)
   общая.
5. **Бустер** (`Config.TIERS.Rocket`, `SledModels.ROCKETS[0..6]`, `buildRocket`, пламя в
   `Effects` по атрибутам `RocketNozzle`/`RocketTier`): заменить форму (мотор/турбина/нитро) и
   цвета пламени (вода — белая пена + брызги, суша — синее нитро).
6. **Следы** (`Config.TRAILS`, `Effects.addSnowTrail`): текстура/цвет частиц — пена, пыль.
7. **Транспорт мешами** (как сделано для саней, 2026-11-08): (1) чертёж по 2–3 фото реального
   объекта — силуэт, габариты относительно сиденья (персонаж на y = +0.5, нос по −Z), узнаваемые
   детали; (2) форма кодом в `scripts/gen_sled_meshes.py` на `scripts/sled_geom.py`: `loft` по
   сечениям `superellipse` (корпус лодки/капот: полуширина, верх, низ по z), `sweep` профиля по
   кривой (полозья, рамы, ручки, трубы, кромки), `revolve` (тела вращения, сопла), `airfoil` (крылья,
   лопасти, спойлер); 1–7 мешей **по цветам** (корпус `main`, детали `accent`, металл/резина/стекло —
   отдельно: MeshPart красится целиком, так редкость перекрашивает модель), ≤ 6k треугольников на
   модель; (3) роли мешей — `SledModels/BodyMeshes.MODELS[id]`, мелочь со светом — Part поверх;
   (4) крепления `MOUNTS` проверить по мешу (фары на поверхности носа, габариты и спойлер сзади, не
   выше плеч персонажа); (5) превью `scripts/preview_sleds.py` (3/4 спереди, камера заезда с
   манекеном, тиры 0/1/4/10) — минимум 2 итерации; (6) стенд `scripts/stand/run.py` — сверка
   отпечатка и число инстансов на сани (у каждого игрока свои: меши сократили 250–600 → 70–90
   инстансов на тире 0). Фолбэк на Part обязателен — меши приходят асинхронно и проходят модерацию.
   Для лодки: корпус — тот же лофт каяка, мотор — `revolve` + `sweep`, для машины — кузов лофтом,
   колёса `revolve` с протектором.

## 6. Миры (`track-architect` + `art-director` + `game-designer`)

На каждый мир: запись в `Config.THEMES` (`name`, `floor`, `wall`, `ground`) + иконка в
`WORLD_ICONS`/`WORLD_IMAGES` (PNG в `assets/ui`) + цвета плитки `WORLD_COLORS` + ветка в
`Track.dressSegment` + наборы в `Props.obstacle`/`Props.traffic` + свет в `Effects.LOOKS`
(`Ambient`, `OutdoorAmbient`, `ClockTime`, `FogColor/End`, цвет неба) + при желании материалы
дна в `buildCrossSection` (как `theme == 3` → песок, `6` → базальт). `LEVELS_PER_WORLD` — длина
мира. Названия «… II» по кругу делает `worldName`.

### Свои 3D-меши для декора (как сделано в #45)
Part-ы дают «кирпичный» силуэт у гор, деревьев, скал; Union/EditableMesh Open Cloud не публикует.
Рецепт: (1) форма кодом — `scripts/gen_meshes.py` (икосфера + гладкий шум + срезы плоскостями для
камня; поверхность вращения с волнистой кромкой для ярусов дерева; поле высот с мягким максимумом
вершин для гор; профиль-уступы для мез; сечение по дуге для арки), 300–1300 треугольников, кадр
«основание на земле, Y вверх», плоские нормали для low-poly, гладкие для снега, UV коробочной
проекцией, белый материал без текстуры; (2) превью PNG (`preview_meshes.py`) — минимум 2 итерации
глазами; (3) деплой грузит `.glb` как Model (права ключа Assets API `asset:read` + `asset:write`),
ID коммитятся из лога; (4) сервер `LoadAsset` → шаблоны MeshPart в ReplicatedStorage, `Clone` +
`Size` по габаритам из `MeshSpecs`; (5) **всегда фолбэк на Part**, Random-вызовы — до выбора пути.
Для воды те же генераторы: валуны берега, рифы (камень с плоским низом), волнорезы (утёс), буи.
Препятствия — из Part (коллизия); меши — декор и слои кадра (ближний / средний / дальний / «вау»).

## 7. Правила, экономика, удержание (`game-designer`; деньги — `producer`)

Перед цифрами — `producer` заполняет `docs/BUSINESS.md` новой игры: целевая аудитория, воронка,
лестница монетизации (копируется отсюда и перетюнится), план привлечения, первые гипотезы.

Переносится как есть, меняются только слова и цифры:
- `Config.F` — формулы апгрейдов; `UPGRADES` — цены и рост; `TIERS` — названия (11/11/11/7).
- `POWERUPS` — шансы/времена; `TASK_POOL` — тексты и иконки заданий (id-шники событий
  `runs`, `distance`, `finish`, `flips`, `smash`, `coins`… оставить — их шлют `server/Runs`/`Rewards`);
  `PLAYTIME_GIFTS`, `CHEST_*`, `TASK_CHEST_*`.
- `RARITIES` (Обычная → Gold → Diamond → Ruby → Galaxy) — для лодок можно «Дерево → Карбон →
  Хром → Золото → Галактика»; это только `name`/цвета.
- `PRODUCTS` — Robux-товары: ID создаёт владелец в Creator Hub.
- Всё числовое добавляй в `Config.TUNABLES` — крутится в игре без деплоя (DEV → Настройка).
- Экономику посчитать скриптом: монет за заезд на уровне N vs цена апгрейда — первый апгрейд
  ≤ 2 заездов, далее каждые 2–4 заезда первые 20 минут.

## 8. Интерфейс, тексты, иконки, звук (`art-director`)

1. Тексты: `grep -rn "сан\|Сан\|рогатк\|Рогатк\|ракет\|Ракет\|снег\|Снег\|лёд\|лед" src` — в
   `HUD`, `LobbyMenus`, `Reveal`, `DevPanel`, `Config` (названия) — заменить на новый словарь.
   Склонения заданий — `forms` в `TASK_POOL`.
2. Иконки: `assets/ui/*.png` (Fluent Emoji 3D, MIT, 256px) — добавить новые (лодка, волна,
   доска, шлем…), положить в папку; деплой загрузит, ID из лога (`UI_DECALS_JSON_BEGIN/END`)
   закоммитить в `decals.json` + `UIDecals.luau`. `UI.EMOJI` — фолбэки.
3. Цвета дизайн-системы — `UI.C`/`UI.KIND` в `UIKit`; места лобби-UI — `shared/UILayout`
   (масштаб `UI.fitScale` — от области под топбаром Roblox, а не от ViewportSize); проверка —
   `scripts/ui_layout_preview.py` (PNG-схема 6 экранов) и DEV → «Проверить UI (телефон)».
4. Звук: `Config.MUSIC_IDS` (свои треки, загруженные владельцем в Creator Hub как Audio — чужие
   не воспроизводятся), эффекты в `Sounds.client` (свист ветра → шум воды / шум шин).
5. Погода: `Effects` — `Snowfall` → дождь/брызги/пыль или выключить; настройка `Snow` в меню →
   переименовать.

## 9. Панель владельца и настройка на лету (`code-reviewer`)

`client/DevPanel.client.luau` читает `Config.SLEDS`, `TIERS`, `ROCKETS`, `THEMES`, `POWERUPS`,
`TUNABLES` — после правок Config вкладки обновляются сами. Проверить только заголовки вкладок
(«Рогатка», «Сани», «Ракета» → свои) и `TAB_ORDER`.

## 10. Проверка и релиз (`code-reviewer` → `qa-tester` → владелец)

1. `luau-analyze src/**/*.luau`; `code-reviewer` по чек-листу.
2. Push → staging; `qa-tester` по `docs/TESTING.md`: уровни 1, 5, 6; все бонусы; магазин;
   выход-вход; F9 чистый; телефон.
3. Creator Hub руками владельца: название, описание, иконка, скриншоты, возрастная анкета,
   Robux-товары (ID → `Config.PRODUCTS`), затем `git tag v1.0.0 && git push --tags` →
   production.

## 11. Порядок работ и объём (ориентир)

| Шаг | Кто | Объём |
| --- | --- | --- |
| 1 словарь + GAME_DESIGN | главный, game-designer | 1 сессия |
| 2 репозиторий, Roblox, секреты | владелец, code-reviewer | 1 час (руками владельца) |

| 4 препятствия, трафик, декор 1-го мира | track-architect, art-director | 1–2 сессии |
