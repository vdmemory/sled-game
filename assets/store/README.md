Рабочее название на иконке — **SLED RUSH** (одинаковое в A и B, чтобы тест мерил картинку, а не
надпись). Шрифт Inter Display Black (SIL OFL), обводка `UIKit.C.ink`. Палитра — `UIKit.C/KIND`.
Папка `assets/store`, а не `assets/ui`: `publish.sh` грузит `assets/ui` как декали.

## Чек-лист модерации и читаемости
- [x] 512×512 PNG, квадрат; проверено в 150×150 и 100×100 — персонаж, ватрушка/сани и название читаются.
- [x] Без мелкого текста, без Robux/цен/«FREE», без чужих брендов, логотипов и персонажей
  (персонаж — безымянная блочная болванка, лицо — две точки и улыбка).
- [x] Без кликбейта: всё на иконке есть в игре (ватрушка, трамплин, монеты, рогатка, сани).
- [ ] Название «SLED RUSH» — рабочее; перед загрузкой проверить поиском Roblox, что нет
  одноимённой популярной игры.

## Загрузка (Creator Hub, по create.roblox.com/docs → Experience icons)
1. Creator Dashboard → игра → **Configurations → Places** → стартовое место (со звёздочкой).
2. В меню места **Icon** → тип **Image** → **Change** → выбрать PNG → **Save Changes**.
3. Иконка видна игрокам только после модерации (обычно минуты–часы).
Через Open Cloud: загрузить PNG как Image-ассет (`POST /assets/v1/assets`), затем
`PATCH /assets/v1/assets/{PlaceId}?updateMask=icon` с `"icon": "assets/<id>"` — ключ только в
GitHub Secrets, вручную не передавать.

## Как тестировать
**Важно (сверено с документацией 2026-11-07):** встроенный A/B в Roblox — **Home page thumbnail
personalization** — работает для **миниатюр Home** (до 1920×1080, ≤ 3 МБ, активны 2–5 шт.),
а не для иконки места. Встроенного сплит-теста иконок нет. Поэтому:

**Вариант 1 — последовательный тест иконок (основной для этих PNG).**
1. Неделя 1: иконка A (с понедельника, 7 полных дней). Неделя 2: иконка B (те же дни недели).
2. Ничего другого на странице игры и в рекламе в эти 2 недели не менять; релизы с крупными
   изменениями — не в эти дни (иначе сравнение испорчено).
3. Метрика: **Analytics → Acquisition / Discovery** — impressions и play-through rate
   (plays / impressions) для Home Recommendations; вспомогательная — first-play bounce и средняя
   сессия новых игроков (картинка не должна обещать то, чего нет).
4. Сколько ждать: ≥ 7 дней на вариант **и** достаточно показов. При CTR ≈ 3% для различия 20%
   (3.0% → 3.6%) нужно ≈ 13 000 показов на вариант; меньше — результат шум, продлить период.
5. Вывод: победитель — у кого play-through rate выше при не худшем bounce. Если разница < 10%
   относительных или показов мало — «ничья», оставить A и перейти к тесту миниатюр.

**Вариант 2 — встроенная персонализация миниатюр Home (точнее, параллельно).**
Сделать из сцен A и B кадры 1920×1080 (расширить фон в `render.js`), Creator Hub → игра →
**Home Page** → **Edit active thumbnails** → загрузить/отметить **Active** 2–5 → **Save changes** →
**Start**. Через несколько часов заполнится таблица **Thumbnail Performance**: Impressions,
Qualified Plays, Average Playtime, **Qualified Play Through Rate**, Winning Segment. Алгоритм сам
отдаёт больше показов победителю, но держит остальных на минимальном трафике — смотреть
QPTR через 7 дней.

## Что записать в `analytics/events.csv`
```
2026-MM-DD,marketing,"Иконка A «Полёт» активна — старт теста иконок #28",assets/store/icon_a.png
2026-MM-DD,marketing,"Иконка B «Рогатка» активна — 2-я неделя теста #28",assets/store/icon_b.png
2026-MM-DD,decision,"Тест иконок #28: A PTR x.x% (N показов) vs B y.y% (M показов) → оставлена …",docs/BUSINESS.md
```
Итог — в `docs/BUSINESS.md` §6 (колонка «Результат»), цифры снимков — `analytics/metrics.csv`.
